# Tender Radar

Учебная практика 1-го семестра магистратуры НИЯУ МИФИ / Simulative, 2026. Виктор Чернышев.

**Задача:** собирать сведения о госконтрактах и приоритизировать поставщиков для дальнейшего рассмотрения менеджером банка или брокером. Результат — объяснимый рейтинг и личный Telegram-бот. Рейтинг не является кредитным решением или доказательством потребности в кредите.

## Что реализовано

- Сбор публичных HTML-страниц реестра контрактов ЕИС и карточек поставщиков: requests, BeautifulSoup, SQLite.
- Воспроизводимый отбор страниц, паузы между запросами, остановка при блокировке/пустой выдаче; фиксация успешного, частичного и неудачного запуска.
- Аналитика на зафиксированном срезе и экспертный скоринг.
- Личный бот: `/today`, `/leads`, `/stats`, `/filter`, `/help`; доступ по chat_id и sender_id владельца.
- Дайджест: сохраняемая очередь, повтор неподтвержденной доставки, продолжение с неподтвержденного сообщения, запрет второго дайджеста за тот же день.

## Границы работы

В работе проверены сбор, хранение, описательная аналитика, правила ранжирования и доставка результата. Пользователь — менеджер, которому нужна очередь компаний для рассмотрения, а не готовое кредитное заключение.

**За рамками:** кредитоспособность и финансовая отчетность компании, реальные заявки и выдачи кредитов, причинная оценка кассового разрыва, промышленный SLA, круглосуточный сервер, ML-модель вероятности сделки. Нет подтвержденных клиентских интервью и коммерческих продаж.

Отсутствие аванса — косвенный признак. 93,73% не означает, что столько же поставщиков хотят кредит. Суммы и доли относятся к выборке, не ко всему рынку. Первую страницу берем всегда, остальные выбираем псевдослучайно; это не простая случайная выборка. Регион в фильтре — адрес регистрации или префикс ИНН, не место исполнения контракта.

## Скоринг

Фильтры: отсутствие аванса, цена от 1 млн, известные даты, срок исполнения не истек; исключаются отдельные типы организаций и поставщики с 8+ контрактами в выборке. При нескольких подходящих контрактах выбирается крупнейший; для бота и дайджеста свежесть/контакт/настройки применяются до этого выбора.

Баллы: сумма 45, длительность 25, свежесть 20, умеренная активность 10. Сумма нормируется логарифмически от 1 до 50 млн, длительность ограничена годом, свежесть падает после 3-го дня до нуля на 30-й. Это экспертная схема, не модель, обученная на сделках.

Проверка весов на срезе: 200 воспроизводимых прогонов, изменение каждого веса ±50% с нормировкой суммы к 100; медианное сохранение состава топ-50 — 88%, минимум — 46%. Рейтинг в среднем устойчивее, чем в худшем сценарии; это не проверка качества продаж. Порог 8 зависит от длины истории. Выявлена одна запись с обратным порядком дат, она не исправлялась догадкой; алгоритмическая классификация предмета закупки также имеет ограничения.

## Запуск

Python 3.9+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd src
../.venv/bin/python -m tender_radar stats
../.venv/bin/python -m tender_radar bot
```

В `.env` в корне проекта задать `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID` личного чата. Не публиковать эти значения. Бот работает при запущенном процессе, бодрствующем компьютере и сети; сбор выполняется отдельной задачей.

На рабочем Mac: сбор ежедневно 09:15 — 2 страницы, до 100 контрактов, пауза 5 с; добор до 20 контактов, пауза 10 с. Нагрузку не увеличивать для демонстрации. При блокировке/пустой выдаче/недоступности добор пропускается, дайджест использует уже накопленную базу с отметкой статуса. Шаблоны launchd в scripts требуют адаптации абсолютного пути под свою машину.

```sh
# Из src: только показать текст, не отправлять
../.venv/bin/python -m tender_radar digest --dry-run
# Повторить только существующий незавершенный дайджест за сегодня
../.venv/bin/python -m tender_radar digest --retry-pending
```

Повтор доставки настроен каждые 30 минут с 09:15 до 21:45 отдельным LaunchAgent и не обращается к ЕИС. При таймауте после фактического принятия Telegram возможен дубль: внешняя доставка не имеет гарантии exactly-once.

## Команды

- `/today`: новые контракты по дате первого попадания в базу и подходящие поставщики.
- `/leads` или `/leads 20`: рейтинг свежих поставщиков с контактом.
- `/stats`: показатели всей базы и поступление за 7 дней.
- `/filter регион=Саратов сумма=5000000` или `/filter region=64 min=5000000`: настройки для списков и дайджеста; `/filter reset` — сброс.

## Структура и ключевой код

| Файл | Назначение |
|---|---|
| src/tender_radar/client.py | HTTP, паузы, повторы, обнаружение блокировки |
| src/tender_radar/parsers.py | HTML → поля контракта и поставщика |
| src/tender_radar/db.py | Таблицы, связи, запись без дублей |
| src/tender_radar/scoring.py | Фильтры, расчет баллов, ранжирование |
| src/tender_radar/digest.py | Формирование сообщений, очередь доставки |
| src/tender_radar/bot.py | Команды, проверка владельца, long polling |
| src/tender_radar/cli.py | Командный запуск, журнал статуса сбора |
| analysis/defense_report.py | Воспроизводимая аналитика и проверка скоринга |

`contracts` ↔ `contract_suppliers` ↔ `suppliers`; отдельно `fetch_log`, `fetch_runs`, `digest_sent`, `digest_outbox`. Настройки и позиция Telegram хранятся в отдельной локальной базе bot_state.db.

## Проверки без сети

```sh
.venv/bin/python tests/test_parsers.py
.venv/bin/python tests/test_scoring.py
.venv/bin/python tests/test_digest.py
.venv/bin/python -W ignore tests/test_bot.py
.venv/bin/python -W ignore tests/test_daily_reliability.py
.venv/bin/python -W ignore tests/test_delivery_queue.py
```

Для воспроизведения аналитики нужен локальный зафиксированный снимок БД; в публичном репозитории есть код и обезличенные агрегаты, но не исходные контакты:

```sh
.venv/bin/python analysis/defense_report.py --db data/snapshots/defense-2026-11-11.db --out analysis/defense-2026-11-11.json --as-of 2026-11-11
```

Снимок создается через sqlite3.Connection.backup. Контрольная сумма приведена в JSON. Типы предметов определяются Python `casefold`, а не стандартным SQLite `lower`, который не обрабатывает кириллицу так же. Ранние запросы srez_queries.sql сохранены как исторический черновик, не источник итоговых цифр.

## Источник и ограничения эксплуатации

Источник — публичные HTML-страницы zakupki.gov.ru. Объем сбора ограничен, массовая выгрузка не производится. Исторически в клиенте отключена проверка сертификата ЕИС; это техническое ограничение прототипа и отдельная задача для промышленного развертывания. Для Telegram проверка TLS не отключается.

Проект подготовлен для учебной защиты 28.11.2026, доклад 7–10 минут. Дальнейшее развитие: проверка рейтинга по обратной связи менеджеров, обогащение финансовыми/рисковыми признаками, пересмотр порога активности, мониторинг и развертывание на сервере.
