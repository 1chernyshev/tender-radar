# Сертификат для клиента ЕИС

Russian Trusted Root CA (RSA). Загружен 13.11.2026 по HTTPS с проверкой
стандартной публичной цепочки, не извлечен из недоверенного ответа ЕИС.

- Официальная страница: https://www.gosuslugi.ru/crt
- Файл: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
- Инструкция интеграции с этим источником: https://developers.tochka.com/docs/tochka-api/certificate
- SHA-256 DER (отпечаток сертификата): `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`
- SHA-256 файла PEM: `936a43fea6e8e525bcc0f81acd9c3d21b4fc4b9b68acea7906d698005afc6504`
- Срок действия: 01.03.2022 21:04:15 — 27.02.2032 21:04:15 UTC.

Только `EisClient` использует этот файл как набор доверенных корней. Проверяются
цепочка, срок действия и имя сайта. Системное хранилище macOS и доверенные
корни Telegram не меняются. Автоматической загрузки сертификатов при старте
нет. При смене цепочки нужно проверить официальный источник и обновить файл;
возврата к `verify=False` нет.

На этом Mac используется Python 3.14 / OpenSSL. Старый Python 3.9 / LibreSSL
2.8.3 при разборе текущего сертификата ЕИС дает `unknown error (_ssl.c:1192)`;
одного добавления корня для старого окружения оказалось недостаточно.
